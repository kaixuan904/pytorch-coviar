 CoViAR：压缩域视频动作识别

 一、项目简介

CoViAR（Compressed Video Action Recognition）是一种面向压缩视频的动作识别方法。传统视频动作识别通常需要将压缩视频解码为连续的 RGB 图像，再提取外观与运动特征；CoViAR 则直接利用视频编码过程中已有的压缩域信息进行识别，以减少完整视频解码和额外运动估计带来的计算开销。

本工程围绕 CoViAR 的三分支识别框架展开。模型分别利用 I-frame（关键帧）、Motion Vector（运动向量，MV） 和 Residual（残差） 表征视频的外观、运动以及运动补偿后保留的局部变化信息，并通过分类结果融合获得最终动作预测。工程包含模型定义、数据读取、训练与测试流程，以及面向残差处理和分支分数融合的实验实现。

 二、核心方法原理

 2.1 I-frame：外观信息

I-frame 是不依赖其他帧进行帧间预测的图像帧，包含相对完整的空间外观信息。I-frame 分支主要学习人物、物体、场景和动作发生环境等视觉线索，为动作分类提供外观依据。

 2.2 Motion Vector：运动线索

运动向量是视频编码器在帧间预测过程中记录的块级位移信息。它能够以较低的表示成本提供运动方向和位移线索，但并不等同于真实光流：其空间分辨率、量化方式和编码策略都会影响运动信息的精细程度。因此，MV 分支适合提供高效的运动提示，但在快速运动、局部形变或复杂背景运动场景中可能存在表征不足。

 2.3 Residual：预测误差信息

残差记录当前编码内容与运动补偿预测结果之间的差异，其中包含边缘、纹理、局部变化以及运动预测未能解释的内容。残差可以补充运动向量中缺失的细节，但其本身也可能包含压缩噪声和复杂纹理，需要通过合适的特征提取方式转化为有助于动作识别的表示。

 2.4 三分支识别与融合

工程采用 I-frame、MV 和 Residual 三类输入分别进行特征学习与分类。各分支从不同角度描述同一段视频：I-frame 提供外观信息，MV 提供运动位移线索，Residual 补充局部变化信息。通过对各分支输出进行融合，可以利用不同表征之间的互补性，降低单一信息来源不足对识别结果的影响。

 三、工程模块

 3.1 模型、训练与测试

基础代码负责数据集读取、模型构建、训练参数配置、模型训练、测试评估及分类分数导出。相关模块覆盖从压缩域数据输入到动作类别预测的主要流程。训练与测试时需要保证数据划分、类别映射、输入表示和模型配置一致。

 3.2 Residual 频域滤波

Residual 频域滤波实验面向残差分支的输入处理。其基本思路是分析残差中的空间频率成分，通过频域滤波抑制部分不需要的高频变化或压缩噪声，并观察残差表示变化对分类性能的影响。滤波强度和频率响应会改变保留的纹理、边缘与细节，因此需要结合验证集结果进行评估，不能预先假定滤波一定能够提升准确率。

 3.3 分类分数融合

分数融合模块用于组合不同分支的分类输出。由于 I-frame、MV 和 Residual 分支的输出分布与数值尺度可能不同，直接相加未必能充分利用各分支信息。实验代码围绕分数归一化、分支权重及融合策略开展比较。融合前应确认各分支输出对应相同的视频样本、相同的类别顺序和相同的数据集划分。

 3.4 数据集与辅助工具

工程中的数据工具用于准备训练和测试清单、检查异常视频、辅助视频重编码，以及组织模型推理所需的数据。相关脚本可以减少数据准备过程中的重复操作，但具体使用方式取决于脚本参数、数据集目录结构和本地环境配置。

 四、整体技术流程

text
压缩视频
   │
   ├── I-frame ─────────→ 外观特征提取 ───────→ I-frame 分类分数 ──┐
   │                                                               │
   ├── Motion Vector ───→ 运动特征提取 ───────→ MV 分类分数 ──────┼──→ 分数融合 ──→ 动作类别
   │                                                               │
   └── Residual ────────→ 残差处理与特征提取 ─→ Residual 分类分数 ┘


整体流程可以分为四个阶段：

1. 压缩域数据获取： 从压缩视频中提取或读取 I-frame、MV 和 Residual 三类表示。
2. 分支特征学习： 将不同表示分别输入对应的识别网络，提取与动作类别相关的特征。
3. 分支分类： 各分支独立输出动作类别分数。
4. 结果融合： 根据设定的融合策略组合分支输出，得到最终的动作分类结果。

 五、运行环境与数据准备

项目运行环境通常涉及 Python、PyTorch、CUDA、视频解码组件及用于编译数据加载扩展的构建工具。不同版本的代码可能对依赖版本有不同要求，应结合项目中的环境配置文件和脚本说明建立环境。

运行前需要准备相应数据集及其划分清单，并确认数据预处理方式与模型输入要求一致。若使用自定义数据路径，应同步修改训练、测试和数据加载脚本中的相关配置。若工程包含 C/C++ 数据加载扩展源码，则需要根据当前系统、Python、PyTorch 和编译器版本进行编译；不能假设预编译模块可跨环境直接使用。

数据集、训练得到的模型权重和完整实验输出通常需要单独准备。使用公开数据集时，应遵守数据集的官方许可和使用要求；引用原始 CoViAR 方法时，请注明相关论文。

 六、使用建议

1. 先检查环境依赖、数据集路径和类别划分文件。
2. 阅读训练参数配置与数据加载代码，确认各分支输入的生成方式和张量格式。
3. 阅读模型定义、训练入口和测试入口，了解模型初始化、检查点保存及评估流程。
4. 在基础流程能够正常运行后，再单独测试 Residual 频域滤波或分数融合模块。
5. 对比实验应使用一致的数据划分、测试设置和评价指标，并保留完整参数与日志。
6. 运行前检查脚本中写死的路径、输出目录、命令行参数及 Python 导入关系。
